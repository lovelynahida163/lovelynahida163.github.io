记录一次在 WSL2 + Ubuntu 26.04 LTS 上从零编译 gem5（ALL ISA, `gem5.opt`）的过程。GCC 15.2、Python 3.14、scons 4.8 这套组合在官方支持范围之外，但实际能编过，过程中踩了几个坑，整理在这里。

## 0. 环境

- Windows 11 + WSL2
- Ubuntu 26.04 LTS（kernel 6.6.87.2-microsoft-standard-WSL2）
- gem5 主分支（`git clone` 当日最新）
- 目标产物：`build/ALL/gem5.opt`

## 1. WSL 启动时的 PATH translate 告警

每次启动 WSL 都会看到一串：

```
wsl: Failed to translate 'D:\anaconda_5_0_1_20230619'
wsl: Failed to translate 'D:\anaconda_5_0_1_20230619\Library\mingw-w64\bin'
wsl: Failed to translate 'D:\Labview-2018 Program\Shared\LabVIEW CLI'
...
```

这是 WSL 在做 Windows PATH → Linux PATH 自动转换时，发现 Windows 侧 `D:\` 上的路径在 Linux 端没有对应挂载点。不影响 gem5 编译，纯噪音。

想消除可以编辑 `/etc/wsl.conf`：

```ini
[interop]
appendWindowsPath = false
```

然后在 PowerShell 里 `wsl --shutdown` 重启。代价是 WSL 里不能再直接调用 `notepad.exe`、`code .` 之类 Windows 程序。如果想保留互操作，就忽略这些告警。

## 2. clone 源码

```bash
mkdir ~/gem5 && cd ~/gem5
git clone https://github.com/gem5/gem5
cd gem5
```

仓库约 226 MiB，30 万 objects，速度看网络。

## 3. 第一次踩坑：`scons -12`

照着印象敲了：

```bash
scons build/ALL/gem5.opt -12
```

scons 直接报：

```
SCons Error: no such option: -1
```

并行任务参数是 `-j`，不是 `-`。正确写法（12 核并行）：

```bash
scons build/ALL/gem5.opt -j12
```

## 4. 第二次踩坑：Python 共享库找不到

在 conda 的 `(base)` 环境下首次运行 scons，报：

```
error while loading shared libraries: libpython3.13.so.1.0:
cannot open shared object file: No such file or directory
Error: Can't find a working Python installation
```

原因：scons 的 `python3-config` 指向 conda 的 Python 3.13，但 conda 默认只装静态库，没有 `libpython3.13.so.1.0`，链接阶段失败。

解决办法：**编译 gem5 时退出 conda，用系统 Python**。

```bash
conda deactivate
which python3   # /usr/bin/python3
```

退出 conda 后 scons 自动找到系统 Python 3.14，这一步过了。

> 不要试图在 conda env 里硬装 shared 版的 Python 去配合 gem5，麻烦不值得。系统 Python 最省心。

## 5. 第三次踩坑：缺一堆构建依赖

再次跑 scons，过了 Python 检测，又卡在 M4：

```
Error: Can't find version of M4 macro processor. Please install M4 and try again.
```

外加一连串 warning：找不到 `protoc`、`png.h`、HDF5、capstone、tcmalloc。这些都是 gem5 的可选/必选依赖。一次性补齐：

```bash
sudo apt install m4 scons \
    protobuf-compiler libprotobuf-dev libprotoc-dev \
    libgoogle-perftools-dev \
    libpng-dev libhdf5-dev libcapstone-dev \
    python3-dev pre-commit \
    build-essential pkg-config zlib1g-dev libboost-all-dev
```

各项对应：

| 包 | 作用 |
|---|---|
| `m4` | 宏处理器，**必需**，缺则直接挂 |
| `scons` | 构建系统本体 |
| `protobuf-compiler` + `libproto*` | trace 支持 |
| `libgoogle-perftools-dev` | tcmalloc，约 12% 性能 |
| `libpng-dev` | PNG framebuffer 输出 |
| `libhdf5-dev` | HDF5 stats 输出 |
| `libcapstone-dev` | 反汇编 |
| `pre-commit` | git hook，写代码时风格检查 |

## 6. 清缓存重编

之前失败的 scons 留下了 conftest 缓存，会误导后续检测。删掉重来：

```bash
rm -rf build
scons build/ALL/gem5.opt -j12
```

这次顺利进入实际编译。控制台会持续刷：

```
[ CXX] ALL/python/gem5/.../something.py.cc -> .o
[EMBED PY] src/sim/System.py -> ALL/sim/System.py.cc
[ CXX] ALL/sim/System.py.cc -> .pyo
...
```

- `[EMBED PY]` 是把 gem5 的 Python 配置脚本转译成 C++ 源码，准备静态链进 `gem5.opt`
- `[CXX]` 是 g++ 编 `.o`
- `[TRACING]` 是生成 debug flag 头文件

ALL ISA 包含 X86 / ARM / RISCV / SPARC / MIPS / POWER 全部 ISA，编译量很大。12 核并行下，vmmemWSL 持续吃 80%+ CPU、6–7 GB 内存。

## 7. 关于 GCC 版本告警

整个编译过程会反复出现：

```
Warning: Detected GCC version 15.2.0 is not officially supported.
         gem5 supports GCC v11 up to v14.2.
```

Ubuntu 26.04 默认 GCC 15.2，超出 gem5 官方支持范围（v11–v14.2）。**实测能编过**，没触发 `-Werror`。如果哪天确实编不过，再考虑装 `gcc-14` 并通过 `update-alternatives` 切换。

## 8. 链接产物

最后一行：

```
[ LINK] -> ALL/gem5.opt
scons: done building targets.
```

`build/ALL/gem5.opt` 就是可执行文件。验证：

```bash
ls -lh build/ALL/gem5.opt
./build/ALL/gem5.opt --help | head
```

跑一个最小例子：

```bash
./build/ALL/gem5.opt configs/learning_gem5/part1/simple.py
```

能看到 `Hello world!` 和 simulation tick 日志即环境 OK。

## 小结

整个流程的核心几个点：

1. `scons -j12` 不是 `-12`
2. 编译 gem5 时**退出 conda**，用系统 Python
3. 一次性把 `m4 / protobuf / hdf5 / png / capstone / tcmalloc` 装齐，省得反复试错
4. 失败一次后 `rm -rf build` 再编，别让 conftest 缓存搅局
5. GCC 15.2 的 warning 现阶段可以忽略
